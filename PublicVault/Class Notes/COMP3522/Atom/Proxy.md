 - is [[Structural Design Pattern]]
 - is [[Wrapper]]
 - Controls access to a wrappee
	 - E.g. A proxy controls access to a database
		 - Validates auth
		 - Caches results
		 - other optimizations
![[DesignPattern_Proxy.png]]
 - Used when:
	 - You want to execute logic before or after primary service logic
	 - Encapsulate and control expensive objects
 - A proxy can:
	 - Be passed to any object that expects the shared interface
	 - Can work even if the original service is not available
 - Follows [[Open Closed Principle]] by introducing new proxies that extend behavior rather than modifying the original service.
 - Disadvantages:
	 - Can complicate the codebase
	 - Can delay service response if the Proxy does extensive work before/after invoking the service
