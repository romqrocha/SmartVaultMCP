- A [[Behavior Design Pattern]]
- Used when an object needs to undergo various steps for processing
- Steps could be:
	- Checks
	- Validation
	- Formatting
	- Security
	- Setup
	- Etc.
- The objects that do the validation are called **handlers**
- Each handler
	- is unique
	- implements the same interface
	- modifies a **request**
	- Has a reference to another handler
		- Depending on the code, may pass the request to another handler
# Why and When
- If your program needs to process different kinds of requests in various ways
- When you need to process in particular order
- If the sequence and order of processing is not known before-hand
- [[Single Responsibility Principle]]
	- Each handler does one thing
	- Decouples the class the invokes the operation from the class that performs the operation
- [[Open Closed Principle]]
	- We can add new handlers without modifying existing handlers or client code.
# Disadvantage
- More classes to maintain
- Some requests may end up handled **if** we don't set up the ordering of handlers properly
