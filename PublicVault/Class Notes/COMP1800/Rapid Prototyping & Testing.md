# The Rapid Prototype Process

- Prototype converts the users’ description of the solution into something they can use and test.
- You get feedback from users
- You refine the prototype based on feedback.

## How much will we prototype?

- The 20% of the functionality that will be used 80% of the time (Pareto’s Rule/The 20/80 Rule)
- Ask yourself what key functionality the user will want to use the most?
- Test that out.

### Low Fidelity Prototypes

- Low Fidelity
    - No color
    - Simple shapes
- Put less pressure on the user
- Allows the designer to be less attached, so they’re more open to changes
- Text can be placeholder/lorem ipsum

### Prototyping principles

- Find the quickest way to give the user an experience
- Doing is the best kind of thinking
- Use materials that ‘move at the speed of thought’
    - Should emulate the experience quickly and effectively so people can learn from the experience.

## User Testing

- Remember Jacob’s Law (Users spend most their time on other sites. This means they prefer that your site works the same way as all the other sites they know.)
- Can the user find what they need?
- Do UI elements create distraction or a barrier between the user and the content?
- C.A.R.P.
    - Contrast Alignment Repetition Proximity
- Can the user finish the task they set out to do?

## Usability Evaluation Methods

- Usability Inspection
    - Look at it
- Usability Testing
    - Summative Testing: Ask at the end what they though
    - Formative Testing: Observe the user during the task.
- You **MUST** do some sort of usability testing session.
- 5 Users is enough to find about 80% of the biggest issues
- A majority can be eliminated within 3 sessions, attended by 5 users per session
- “0 users give 0 insights”
