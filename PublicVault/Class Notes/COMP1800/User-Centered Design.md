- Most users are neither beginners or experts, so we focus on the Intermediate users when designing
- Beginner/Expert user are called the “Extreme User Groups”
- Optimize for Intermediate!

- You can’t please everyone - you need to pick a target and work towards them
    - e.g. You cant design a pen that pleases people who use Gel Pens, Ballpoint Pens, and Fountain Pens simultaneously.
- The user you want to design for is your **Persona**
- A **Persona** is a detailed description of a imaginary person who stands in for a user of your system
- A fictional, yet realistic, depiction of a target user
# Designing a Persona

- First, research your users
- From that data identify patterns
- Group those patterns into clusters
- Differences between Personas should reflect the differences that matter
    - Behaviors - What people do
    - Needs - Why they need to do them
- Make assumptions about users clear
- Place emphasis on SPECIFIC users rather than “everyone”
- Naturally limit our choices, which helps us make better designs
- You should only have a small number of Personas
    - The exact number will depend on duration of research phase, and amount of features you can realistically deliver
# Red Route

- Used to identify features
    - Helps find “Blockbuster features” - the small set of features that deliver the most value
- Helps discover high vs low priority deliverables
# Feature

- A distinct function that solves a specific problem
- You should be able to answer the following when deciding to add a new feature to your app
    - **What** problem are you solving?
    - Why is the using choosing to solve that problem?
    - How are you solving the problem?
- Summarized: How frequently will this feature be needed?
# User Story

- Scenarios to tell about the users goals and actions
- Follows a specific structure
    - As a…..(Persona/Group)
    - I want to….(End Goal/Experience Goal)
    - So that I can….(Motivation Goal/Life Goal)
- Ask yourself if this is something you can see the persona say?
- It should have adjectives/verbs/adverbs

# Task Flow

- The Steps
- Tend to be linear - show expected steps a user needs to take.
    - Focus on the main success scenario
- NOT a User Flow
    - User Flow has branching choices
- Multiple task flows make up a User Flow

# Wire Flow

- A combination of a wireframe and a task flow
- Visualizes the task flow
- Arrows between wireframes that show where a user would click and where it would lead
- First part of Ideation phase
- Does not include details
